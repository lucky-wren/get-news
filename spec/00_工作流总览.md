## 1. 这套流程到底交付什么

一句话：**一份每天一更、面向普通大众的结构化每日要闻 Excel**，文件名 `daily_news_YYYYMMDD_20h.xlsx`，采集窗口 `(前一晚 20:00, 当晚 20:00]`（Asia/Shanghai，左开右闭）。

不是新闻聚合页，不是口播稿，不是网页工作台，也不是数据库。它是一张可下载、可核对、可复算的表：每条新闻都能追到独立原文，每个分数都能复算，每条被剔除的稿子都有留痕，每个渠道都申报了触达状态。

**目标读者是普通人，不是行业读者。** 收的是衣食住行、工作就业、医保社保、工厂与制药、医药、AI 发展、新能源、裁员、地方政府负债、房地产、企业倒闭与资不抵债、社会议题这类「大多数人会关注、跟日常切身利益贴近」的资讯。国家机构发布的稳中向好、远期规划、与普通人无关的会务人事稿一律不要。国际动态只看战争与武装冲突、灾害与公共卫生、突发事故与重大安全事件三类重大突发。

## 2. 三条链路必须分开（最重要的一节）

历史上所有「产物不对」「渠道不全」「status=degraded」的争论，根子都是把这三条混成了一条。

| | ① 定时任务（调度器） | ② 会话内补跑 | ③ 仓库侧自动采集（另一项目） |
|---|---|---|---|
| 谁执行 | 平台定时任务，到点由调度系统按 instruction 执行 | AI 在对话里按同一份 instruction 走一遍 | 代码仓库的 Actions 在境外 runner 上跑 Python |
| 数据怎么来 | instruction 指挥的联网检索与逐条回查 | 同左，平台联网检索 + 逐条回查独立原文 | `collectors.py` 的 RSS / 热榜 API / 搜索 API / site: 定向适配器 |
| 要不要 API Key | 不需要 | 不需要 | 需要，缺 key 时降级 |
| 三平台（微博 / 抖音 / 微信） | 可达，公开词条 → 回查独立原文 → 成稿 | 同左 | 适配器无 key 时申报「未触达」 |
| 产物去向 | **本地文件推送到对话里给用户下载** | 同左 | 仓库根目录的 `data.xlsx` + `latest.json`，由 Actions 自己 commit |
| 执行回执 | 配置侧看不到，是否跑成只能看用户有没有收到 xlsx | 当场可见，产物直接给 | Actions 日志可见 |
| 状态字段 | 无 | 无 | `status` / `degrade_reason` / `ai` / `verify_states` 等 |

**硬约束（给其他 AI 的禁止项）**

- 定时任务链路和会话内补跑链路**不产出** `latest.json`，也不写 `status` / `degraded` / `SEARCH_PROVIDER` / `LLM_*` / 适配器「未触达」这类字段。表里出现这些，就是把仓库代码产物冒充了定时任务产物。
- 反过来，仓库 Actions 的适配器申报**不能**贴到会话内批次的口径表上。会话内用平台检索能力拿到 30 / 88 / 106 / 125 个渠道是真实的，不能因为「脚本没配 key」就写成「渠道未触达」。
- 在线腾讯文档作业总表只是**规则底稿**，本身没有定时器；它不接收产物、不落地 xlsx。
- 定时任务**不写仓库、不写在线文档、不发邮件、不传网盘**。产物只有一处：对话里的本地文件下载。

## 3. 定时任务本体（链路 ①）

### 3.1 参数

| 项 | 值 |
|---|---|
| 标题 | 每晚要闻速览出表 |
| 类型 | 重复任务 |
| 规则 | `FREQ=DAILY`，每天 20:00:00 |
| 时区 | `Asia/Shanghai` |
| 首次触发 | 2026-11-14 20:00:00 |
| 状态 | 启用 |
| 交付 | 产出 Excel，作为本地文件推送给用户下载 |

另两条同类历史任务处于停用状态，不属于当前链路，不要启用、不要参考其口径（其中一条仍写着「来源列保留可点击 URL」「导入腾讯文档在线表格」，与现行口径相反）。

### 3.2 instruction 的六节结构

完整全文在 `01_定时任务_instruction_现行全文.md`，不要在这里复制第二份。六节是：

| 节 | 管什么 |
|---|---|
| 一、采集与窗口 | 窗口与整点归属、8 个上位大类逐组检索、三平台词条回查、渠道覆盖表、独立原文准入、拼盘稿拆分 |
| 二、准入 | 判定顺序、大类级准入、大众贴近度正面清单、三类强剔除、判据澄清、判定式、国际三类门禁、F1–F4 |
| 三、聚类与多渠道 | 采集层去重、cross_score、来源列契约、议题簇与事件层分离 |
| 四、打分 | I/C 档位、T、V、H 通道、等级映射、gin / cap / Final_adj |
| 五、编排 | U 与表 R 八组、头部三席、前窗 10 条、相邻同类打散、逐项留痕 |
| 六、展示与交付 | 12 列、来源列、摘要规范、五工作表、候选池定义、口径正文与附录、全文写法、质检清单、文件名与交付方式 |

### 3.3 改口径时改哪里

- 只改筛选口味 → 改 01 的第二节「大众贴近度正面清单 / 三类强剔除 / 国际门禁」，再同步 02 的 §4.1、03 的 §3.2–3.4
- 只改来源列格式 → 改 01 的第三节与第六节「来源」，再同步 03 的 §4.2 与 02 的 §1.3
- 只改候选池定义 → 改 01 的第六节，再同步 02 的 §4.13 / §11 / §12、03 的 §4.1 / §4.4 / §5
- **不要改标题、时间、时区、启用状态**，除非用户明说
- **不要顺带润色其他章节**，历史上多次因"顺手改一下"导致两份文档打架

### 3.4 执行回执的诚实边界

配置更新 ≠ 确认调度跑成。配置侧只有任务定义，没有执行历史、日志或产物副本。过了 20:00 不等于跑成了，也不等于没跑。判断只能看用户那边有没有收到 `daily_news_YYYYMMDD_20h.xlsx`。**不要向用户承诺"今晚已经出了"，也不要说"确定没跑"。**

## 4. 会话内补跑（链路 ②）逐步 SOP

触发场景：用户说「现在跑一遍」「跑一下 X 日晚 8 点到 Y 日晚 8 点的」「我看看效果」，或者定时任务产物没收到需要补一份。

**关键前提**：补跑用的是与定时任务**同一份 instruction**，不是仓库代码，不是规则引擎回放，不是把上一版 xlsx 改几个字。历史上多次出错都是因为拿一份旧台账反复回放、只重写口径表文字。

### Step 0 · 锁定窗口与执行身份

- 窗口固定 `(前一晚 20:00, 当晚 20:00]`，左开右闭；20:00 整点归当批，与前一批不重叠
- 在口径表写清「执行方式 = 按任务 instruction 在会话内补跑，不是调度器执行，产物不来自仓库流水线」
- 在口径表写清「产物去向 = 本地文件推给用户下载，不进仓库、不写在线文档」
- 不要引入 `status` / `degraded` / `latest.json`

### Step 1 · 全大类逐组检索

按 8 个上位大类逐组联网检索：民生服务 / 财经市场 / 科技与产业 / 文娱与热榜 / 重要赛事 / 重大突发与司法 / 国际动态 / 社会治理与养老。

- **采集阶段保持全大类检索**，禁止因为「目标读者是大众」就把检索词框死在民生刚需里；贴近度只在准入阶段判定
- 覆盖 `03_作业总表.md` §2 的渠道分组；★必采、☆按窗口热度、✗仅作热度参考
- 渠道含微博、抖音、微信；微信取「搜一搜·搜索发现」词条
- 每条都要能说出「哪个渠道、哪篇独立文章」

### Step 2 · 逐条回查独立原文（决定质量的一层）

这一层是会话内补跑与纯代码链路的根本差距，也是数据脏不脏的分水岭。

| 要拿到 | 判定 |
|---|---|
| 可点开、专门报道该事件的独立文章 | 节目单、首页栏目、汇编早报目录项、结构化行情 / 比分表、站点首页 URL 一律剔除并留痕 |
| 发布于窗口内的时间证据 | 标题 / 正文里的月日可能是事件日期、周报区间或往期复盘，**只留痕，不据此反推发布时间**；相对时间串（"16 hours ago"）是抓取时刻倒推，不换算成 ISO 写进发布时间 |
| 事件概述（谁 / 何时 / 何地 / 数字 / 发生了什么 / 可行动项） | 社交平台热榜不能只写话题名 + 热度值；查不到事件正文的词条按独立原文准入剔除，进附录 15 |

**热榜词条正确顺序**：词条 → 联网回查带事实的独立原文 → 基于原文写成可核对的事件概述 → 进主表，来源标真实媒体，发现渠道进附录 15。**不允许**凭话题名猜内容、不允许把模型扩写当原文。

### Step 3 · 拼盘稿拆分

- 首段列举导语或「同榜还有… / 另有…」的罗列尾巴裁掉，主体事件必留
- 尾巴里每个词条拆成独立候选行、逐条回查独立原文；未取得原文的进附录 15，不静默消失
- 纯汇编母行剔母行，但把它列出的词条全拆出来
- 叙述性尾巴（援引 / 报道称 / 维持在 / 同比等）不切成假词条
- 裁剪回退到上一个完整句末，不留半句

### Step 4 · 建「窗口内全部数据」候选池

**这是最常被做错的一张表。** 定义（来自 01 第六节）：

> 采集窗口内、标题 / 内容摘要 / 来源三字段齐备，且上位大类与分类标签合规的**未经筛选处理**数据。准入只做窗口过滤与字段校验，不施加大众贴近度筛选、三类强剔除、国际门禁、F1–F4、同事件合并、议题簇合并与展示编排。

- 主表是候选池的**子集**，不是候选池复制主表
- 池内评级列（`Final_adj` / 等级 / 原始 Final / 分数序 / 事件主键）一律置 `—`
- 展示序为采集序 1–N，不参与编排
- 被口径剔除的文娱 / 赛事 / 选举换政 / 国际形势 / 重大突破 / 成就宣传 / 远期规划稿、被同事件或议题簇合并掉的不同写法与侧面，**全部保留、不删不改**
- 不进池的：仅话题名或热度值的词条（进附录 15）、摘要未完整留存的检索线索、超窗口条目（进附录 4），逐条在「候选池边界留痕」列明

基准产物中：候选池 105 条，主表 70 条，池内另有 35 条经筛选或合并未进主表。

### Step 5 · 准入（只决定收不收，不进评分、不改位次）

判定顺序：**大类级准入 → 大众贴近度准入 → 国际动态重大突发限定 → F1–F4 低价值过滤**

**大众贴近度判定式**

```
reject_mass = ACHIEVEMENT_STRONG OR FAR_FUTURE OR UNRELATED
keep_mass   = MASS_TOPIC_HIT OR NATIONAL_HOT
先算 reject_mass，命中即剔；未命中再看 keep_mass，命中即通过；两者皆未命中则剔
```

- 档位取 `strict`，可选 `moderate` / `off`，取值与逐条恢复开关写进口径说明
- 词组表可核对，**禁用裸词**（裸「主权」「领土」「就医」「失业」「物价」「突破」等都会误命中）
- 逐条判定表列命中词组、reject 分支、keep 分支、判定结论、命中总数与误伤数

**三类强剔除**

1. 成就宣传与态势综述 —— 以「稳中向好」「同比增长」「再创新高」「成效显著」「持续向好」主导、无具体受影响对象与可行动项的稿；政府机构发布、企业发布、媒体转述一体适用
2. 远期规划与未落地 —— 拟建、规划中、征求意见稿、框架协议、意向签约、多年后目标、趋势预测、展望前瞻；已生效 / 已开工投产 / 即时可办理 / 已公布具体执行日期的不剔
3. 与普通人无关的机构动态 —— 会见出席、会务预热、人事任免、外事礼宾、内部评优、行业年会、纯政策解读、无落地动作的部委通报

**判据澄清（极易翻车）**：剔除看稿件性质，**不看发布主体**。机构名不得单独当删除开关。油价调整、气象预警、医保目录、社保办理、供暖退费、疫苗、限行、放假安排这些即时可行动信息一律保留并归入正面清单。

> 真实教训：「国家统计局：通讯信息服务类零售额较快增长」要剔（态势综述）；「本轮成品油调价窗口 11 月 26 日 24 时开启」要留（即时可行动）。前者是稿件性质问题，后者标题里的 11-26 是**未来调价日期**，不是发布时间，不能判成历史稿。

**国际门禁**：只保留「战争与武装冲突 / 灾害与公共卫生 / 突发事故与重大安全事件」三类，标 `intl_important`。重大突破、选举换政、国际形势、中性国际资讯一律剔。例外：直接波及境内普通人切身利益（跨境航班大面积取消、进口药断供、境外灾害涉中国公民、跨境价格或供应突变）按民生条目保留并标注依据。某类 0 条或零国际条目须显式声明是采集缺口，不得用无该类条目的批次冒充口径已验证。

被剔条目逐条留痕、不删不改、不参与 `gin` / `Final_adj` / 截断 / 覆盖保底，`must_include` 同步移出。

### Step 6 · 聚类、多渠道、议题簇

- 采集层只去「标题 + 渠道 + URL 全同」的完全重复，同事件不同渠道一律保留
- 准入后按 2-gram Jaccard / LCS / 共享数字锚点 / 事件词组保守聚类，统一事件主键；数字锚点须带单位或小数且标题共享中文实词
- `cross_score = min(12, (独立信源渠道数 − 1) × 3)`，只进编排分 U，不进 H / V / Final，不冒充实测热度
- 主表与前 10 按事件主键去重；**候选池不去重、不合并**
- 议题层与事件层严格分离：事件层按 eid 合并同一件事的不同渠道稿，计入 cross_score；议题层按主体词 + 动作词识别同一议题下不同侧面，主表与前 10 每簇保留 1 条代表条，其余完整内容进附录 17，**议题层不参与 cross_score**
- 议题主体词只认标题（摘要常夹带国名，允许摘要命中会把不相干稿拉进簇），动作词可来自标题或摘要；至少 1 个主体词且主体与动作合计 ≥2 个不同词才归簇
- 代表条优先取簇内 `Final_adj` 最高者，不按摘要长度选；代表条摘要保持原文，不塞入被合并条内容

### Step 7 · 打分（数值不可为编排结果改动）

细则见 `02` §4.2–4.8，这里只列必须复算的公式：

```
I = min(20, I_base + I_func)          I_base = 5（含明确受影响对象）否则 3
C = min(10, 1 + C_func)
V = (0.24T + 0.18I + 0.14A + 0.10C + 0.06M + 0.10V核实) / 0.82 × 5
Final = V / 82.32 × 100              （H 通道关闭时）
等级按原始 Final 机械映射：S≥85 / A 70–84.9 / B 55–69.9 / C 40–54.9 / D<40
Final_adj = Final − 6 × min(gin − 1, cap)
```

- 信息功能档位 I/C 单条取最高一档、不叠加，禁用泛词裸词，不按类目名称加分
- 已在准入剔除的条目不进打分；「重大数据」「科技工程突破」若属成就宣传或远期规划稿，按三类强剔除先行剔除
- T 为「发布时间距窗口中点小时差」的样本自适应百分位（最近→25，最旧→0），禁止 `has_update` 系数；`pub` 缺失取批内已知时刻年龄中位数
- H 通道：>70% 条目无平台后台阅读 / 播放 / 讨论数时 P/H 一律置 NULL，口径声明「H 通道关闭、Final 仅反映价值分 V」；严禁构造虚假 H、不补零、不二次归一化、不把多渠道说成实测热度
- `gin` 按上位大类内 Final 降序、按事件主键去重计数；`cap` 由信息功能档位触发（4/3/2），λ=6；展示分可为负、不加下限、不手工挪位次
- D 级如实标注，不作准入剔除

### Step 8 · 编排（只改展示序）

```
U = daily_score（表 R 八组，min(12, 4×命中不同组数 + min(4, 命中词组总数)))
  + cross_score
  + 8×clip(Final_adj / 批内最大, 0, 1)
  + 重要国际动态加权 6
  + 可配标签加权
```

表 R 八组：天气与出行 / 物价与消费 / 房价与居住 / 工作与收入与社保 / 医药与医保 / 产业与就业（工厂、制药、AI 发展、新能源、裁员、企业倒闭与债务、地方政府负债）/ 社会议题 / 公共服务。

- 天气不硬置顶，作为高相关组之一自然靠前
- 头部三席独立判定：资格池 = `cross_score>0 且 daily_score>0`；`head_score = 1.8×daily_score + 1.5×cross_score + 6×clip(Final_adj/批内最大,0,1)`；逐槽在「上位大类 ≠ 上一条」候选里取最高；头部不参与覆盖保底换出
- 前窗 10 条：同一大类最多 3 条（重要国际动态名额 4），同一六类标签最多 1 条；未被覆盖但有准入条目的大类做覆盖保底换入并留痕；容量不足时放宽上限并如实声明，不编造凑数
- 相邻同类打散：前窗相邻同大类必须为 0；主键上位大类、次级分类标签，U 差 ≤1.0 时优先错开；front→tail 边界传递大类与标签

- 展示序与 `Final_adj` 严格降序不一致须如实标注，不得包装成公式结果

## 7. 常见坑清单（全部来自真实翻车，逐条当禁止项读）

1. **别把仓库代码产物当定时任务产物**。表里出现 `status=degraded`、`latest.json`、`SEARCH_PROVIDER`、适配器「未触达」，就是混了链路。
2. **别把「无 key / 未触达」写进会话内批次口径**。平台检索能力能拿到三平台与聚合流词条，这与脚本适配器是两回事。反过来也不要把会话批次说成「113 渠道全量」。
3. **标题里的月日不是发布时间**。「油价 11 月 26 日调价窗口」是未来事件日期，稿件发布于 11-17 就在窗口内；判成历史稿剔除是错的。
4. **正文里引用的年份不是发布时间**。「看多 2027 年金价」是预测目标年，不是 2027 年发的稿。
5. **相对时间串不是发布时间**。`16 hours ago` 是抓取时刻倒推，只登记进「时间依据」，不换算成 ISO 写进「发布时间」。
6. **剔除看稿件性质，不看发布主体**。国家统计局的「零售额较快增长」要剔，国家发改委的油价调整要留。机构名不得单独当删除开关。
7. **别让「带单位数字」救下成就宣传稿**。态势词命中且非即时可行动就该剔，`416464 亿元、同比增长 1.0%` 不是保留理由。
8. **候选池不是主表复制一份**。把主表 70 条连同 `Final_adj`、等级、分数序逐格复制成第三张表，是最典型错误。候选池必须保留被剔除与被合并的条目，评级列置 `—`。
9. **议题簇不能虚增多渠道热度**。多家媒体报道同一冲突的不同侧面，议题层不得计入 `cross_score`。
10. **三平台词条必须先回查再成稿**。只有话题名 + 热度值的行进附录 15，不进主表；不许凭话题名猜内容。
11. **摘要不许带网页残渣**。导航栏、`字体: 小 中 大`、分享按钮、图片署名、公司档案页字段、半截句、纯目录，全部要在清洗层剔掉；抽取式失败时不要把原始 snippet 原样塞进单元格。
12. **采集工具名不是渠道**。`serper · 新浪财经 · 凤凰网` 里的 `serper` 要去掉；也不要编造 `Sh` 这种截断 slug 当媒体名。
13. **数量少先查台账**。若主表只有 8 / 23 条，先看是不是只喂了一份 27 条或 41 条台账、只开了 1 个采集适配器，而不是去改口径措辞。
14. **别拿「重大数据 / 科技工程突破」当成就宣传的豁免**。若稿件本身属三类强剔除，先剔再谈打分。
15. **正文不写过程性表述**。「本轮剔除了 N 条」「按用户口径保留」「其余全部剔除」这类话只准进口径表，不准进标题与摘要。
16. **渠道覆盖表要逐条申报**。某大类 0 条时写明是采集缺口还是按口径剔除，两者不得混写；不得静默不采、不得编造凑数。
17. **全文不许出现「根据搜索结果」「按内部规则」等来源性措辞**。
18. **配置更新不等于调度跑成**。不要向用户承诺「今晚已经出了」，也不要说「确定没跑」。
19. **不要拿历史批次的 xlsx 当现行口径**。包内 `参考_20261116_历史批次_仅作渠道对照.xlsx` 只用来看渠道能铺多广，其来源格式与筛选口径均非现行版。
20. **别一次交付两份互相打架的文档**。改口径后要全局扫一遍旧表述，只交一套说法；仲裁规则见 §0。
