## 三条链路，别混

| | 定时任务 | 会话内补跑 | 仓库侧自动采集（另一项目） |
|---|---|---|---|
| 谁跑 | 平台调度器到点按 instruction 执行 | AI 在对话里按同一份 instruction 走一遍 | 代码仓库 Actions 跑 Python |
| 要 API Key 吗 | 不需要 | 不需要 | 需要 |
| 产物去哪 | **本地文件推到对话里下载** | 同左 | 仓库里的 `data.xlsx` + `latest.json` |
| 状态字段 | 无 | 无 | `status` / `degraded` / `ai` 等 |

**本包不含**仓库侧采集代码、API Key 配置手册、部署包、在线文档链接、工作台页面。表里若出现 `status=degraded`、`latest.json`、适配器「未触达」，就是把第三条链路的产物冒充了前两条。

## 现行口径一句话

面向普通大众：衣食住行、工作就业、医保社保、工厂与制药、医药、AI 发展、新能源、裁员、地方债、房地产、企业倒闭与资不抵债、社会议题要收；国家机构发布的稳中向好、远期规划、与普通人无关的会务人事稿不要；国际动态只看战争冲突、灾害公卫、突发事故三类重大突发。来源列写 `渠道 · 渠道`（渠道间带空格 ` · `，平台内部 `·` 不带空格）。第三张表「窗口内全部数据」是**未经筛选的候选池**，评级列置 `—`，主表是它的子集。

## 交付边界（如实保留）

- 定时任务产物只有一处：对话里的本地 xlsx 下载；不写仓库、不写在线文档、不发邮件、不传网盘
- 配置侧看不到调度执行回执，跑没跑只能看用户有没有收到文件；不要承诺「今晚已经出了」
- 会话内补跑 ≠ 调度器执行，是按同一份 instruction 当场走一遍
- 会话内靠逐条回查独立原文做语义判断；纯代码链路只吃搜索片段，无法补出原文没有的细节
- 微信「搜一搜·搜索发现」没有公开免鉴权全网接口，无结果就如实申报，不假装有数据
- 会话批次铺到的渠道是真实采集结果，但不得宣称「113 渠道全量」
