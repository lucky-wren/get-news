按《每日要闻筛选评级SKILL.md》执行全流程，产出结构化每日要闻 Excel。目标读者是普通大众，只收大多数人会关注、与日常生活和切身利益贴近的资讯。

一、采集与窗口
- 采集窗口 (前一晚 20:00, 当晚 20:00] 左开右闭，整点归属与零缺口：20:00 整点发布归当批，与前一批不重叠。超左/超右边界条目逐条写明时间证据，不回溯补采、不推测补写；发布时点未取得标「时点推定」，不补造具体时刻。
- 按 8 个上位大类（民生服务 / 财经市场 / 科技与产业 / 文娱与热榜 / 重要赛事 / 重大突发与司法 / 国际动态 / 社会治理与养老）逐组联网检索，覆盖信源清单全部渠道组；★必采、☆按窗口热度、✗仅作热度参考。采集阶段保持全大类检索，禁止按题材或大类框定检索范围、禁止跳过任何大类、禁止把检索词框死在民生刚需里；大众贴近度只在准入阶段判定，不回溯收窄检索词。各类条目一律正常进评级与准入判定，不因题材先验淘汰。
- 渠道含抖音、微博、微信；微信取「搜一搜·搜索发现」词条，词条只是发现入口，每条须回查独立原文后成行。三平台无公开接口时走搜索 API site: 定向，无 key 逐渠道申报「未触达」，不编造条目。平台后台阅读 / 播放 / 讨论数拿不到，H 通道保持关闭，三平台只作独立信源计入多渠道重复度。
- 逐渠道在渠道覆盖表申报「已触达 / 未触达 / 按准入剔除」及条数；某大类准入后 0 条须写明是采集缺口，因筛选口径剔除导致的 0 条须写明「按大众贴近度口径剔除，非采集缺口」，不得静默不采、不得编造凑数、不得把两类原因混写。
- 独立原文准入：只收可点开、专门报道该事件的独立文章且 URL 指向该具体文章；节目单、首页栏目、汇编早报目录项、结构化行情 / 比分表、站点首页 URL 一律剔除并逐条留痕。社交平台热榜不能只写话题名 + 热度值，须讲清大概（谁 / 何时 / 何地 / 数字 / 发生了什么 / 可行动项）；查不到事件正文的词条按独立原文准入剔除。
- 多事件拼盘稿拆分优先：首段列举导语或「同榜还有… / 另有…」的罗列尾巴裁掉，主体事件必留；尾巴里每个词条拆成独立候选行并逐条回查独立原文；未取得原文的进附录 15「线索待原文」留痕，不静默消失；纯汇编母行剔母行但把它列出的词条全拆出来；叙述性尾巴（援引 / 报道称 / 维持在 / 同比等）不切成假词条。裁剪回退到上一个完整句末，不留半句。

二、准入（只决定收不收，不进评分、不改位次）
- 判定顺序：大类级准入 → 大众贴近度准入 → 国际动态重大突发限定 → F1–F4 低价值过滤。被剔条目逐条留痕、不删不改、不参与 gin / Final_adj / 截断 / 覆盖保底，must_include 同步移出。
- 大类级准入：EXCLUDED_GROUPS 整类剔除；GATED_GROUPS 仅留命中「特别重要」事实字段者（可核对词组，如涉台 / 中国使馆 / 中国领空领海等，禁用裸「主权 / 领土」）。禁止按题材先验淘汰。
- 大众贴近度正面清单（命中即通过贴近度，词组表可核对、禁用裸词）：衣食住行与物价消费、工作与就业（含裁员、欠薪、招聘、工时、劳动争议）、医保与社保（含药品目录、报销比例、养老金、公积金、异地结算）、工厂与制造业、制药业与医药（含药价、集采、新药获批、短缺药）、AI 发展（含产品发布、产业落地、监管与就业影响）、新能源（含车、电价、储能、充电）、地方政府负债与化债、房地产（含房价、房贷、烂尾、保交楼、交房、租房）、企业经营恶化（倒闭、资不抵债、破产重整、退市、大面积关店）、社会议题（教育、医疗、养老、交通出行、环境、公共安全、消费维权、食品安全）等与普通人切身利益或日常行动直接相关的条目。全民性热点同样通过：重大天气与权威预警、全国性公共安全事件、现象级文娱与全国性赛事结果、涉及大范围人群的价格或政策变动。小众粉丝向、行业内部、无公共性的花边不通过。
- 三类强剔除（命中任一即终止，逐条留痕）：
  ① 成就宣传与态势综述：以「稳中向好」「同比增长」「再创新高」「成效显著」「持续向好」等表述主导、无具体受影响对象与可行动项的稿件；由国家政府机构发布、企业发布或媒体转述的同类稿一体适用。
  ② 远期规划与未落地事项：拟建、规划中、征求意见稿、框架协议、意向签约、试点意向、多年后目标、趋势预测、展望、前瞻；含已生效、已开工投产、即时可办理、已公布具体执行日期字段的不剔。
  ③ 与普通人无关的机构动态：会见出席、会务筹备与预热、人事任免、外事礼宾、机构内部评优、行业年会、纯政策解读、无落地动作的部委通报。
- 判据澄清：剔除看稿件性质，不看发布主体；机构名（国务院 / 发改委 / 外交部等）不得单独当删除开关。政府机构发布的即时可行动民生信息（油价调整、气象预警、医保目录、社保办理、供暖退费、疫苗、限行、放假安排、退费）一律保留，归入正面清单。
- 判定式：reject_mass = ACHIEVEMENT_STRONG OR FAR_FUTURE OR UNRELATED；keep_mass = MASS_TOPIC_HIT OR NATIONAL_HOT。先算 reject_mass，命中即剔；未命中再看 keep_mass，命中即通过；两者皆未命中则剔。贴近度档位取 strict，可选 moderate / off，取值与逐条恢复开关写进口径说明。逐条判定表列命中词组、reject 分支、keep 分支、判定结论与命中总数、误伤数。
- 国际动态重大突发限定：只保留「战争与武装冲突 / 灾害与公共卫生 / 突发事故与重大安全事件」三类重大突发事件并标 intl_important；「重大突破 / 选举换政 / 国际形势」及表 G-中性（自贸区 / 议定书 / 国际标准 / 汇率 / 全球机构等）、表 G⁻ 低重要度、其余中性国际资讯一律剔除并逐条留痕。例外：该事件直接波及境内普通人切身利益（跨境航班大面积取消、进口药断供、境外重大灾害涉中国公民、跨境价格或供应突变）时按民生条目保留并标注依据。INTL_GEO_SIGNAL 境外主体信号前置，命中明确国家 / 地区 / 组织名优先归国际动态，分类只作元数据。附录 13 逐条列境外信号、三类标签、判定依据与剔除原因；口径正文写「国际动态仅重大突发」声明，列保留 / 剔除 / 重要条数与三类逐类计数，某类 0 条或零国际条目须显式声明是采集数据缺口，不得用无该类条目的批次冒充口径已验证。
- F1 纯规划 / 条例 / 征求意见、F2 单市区县非紧急、F3 纯地方政务局部节点、F4 软文 / 特写 / 成就抒情（命中表 H 词组 AND 未命中任何正向信息功能档位 AND 无带单位实质数字，三条件缺一不可），命中即过滤、不进打分。F1 与「远期规划与未落地事项」重叠时按三类强剔除统一判定，不重复计数。

三、聚类与多渠道
- 采集层只去「标题 + 渠道 + URL 全同」的完全重复，同事件不同渠道一律保留；准入后按 2-gram Jaccard / LCS / 共享数字锚点 / 事件词组保守聚类，统一事件主键，原始 eid 留 eid_raw 逐对留痕。数字锚点须带单位或小数且标题共享中文实词，避免不同事件误聚。
- cross_score = min(12, (独立信源渠道数 − 1) × 3)，只进编排分 U，不进 H / V / Final，不冒充实测热度；全单源批次如实写 0，不编造。
- 主表与「排名最靠前的10条」按事件主键去重，完全重复行 0；「窗口内全部数据」是筛选前的采集候选池，只去采集层「标题 + 渠道 + URL 全同」的完全重复，不按事件主键去重、不做事件层或议题层合并；代表条「来源」统一写 `渠道 · 渠道 · 渠道`：只列可核对的平台 / 媒体名，渠道之间用带空格的间隔号 ` · ` 连接，平台名内部层级分隔符沿用不带空格的 `·`（如 `微信·搜一搜·搜索发现`、`抖音·热点`），据此可无歧义切分。不编号、不用竖线、不带链接、不带占位、不写括注、不追加重复计数标记，不把多平台糊成一坨、不编造渠道名；格式不符一律置空并逐条留痕。独立原文 URL 仅用于采集准入与事实核对，不写入来源列。被合并渠道记录一条不丢，全进附录 12b。
- **议题簇去重与事件层严格分离，两者不可混用**：事件层按 eid 合并同一件事的不同渠道稿，计入 cross_score；议题层按可配置的主体词 + 动作词词组表识别同一议题下的不同侧面（默认内置「美伊冲突与海湾局势」「俄乌局势」两组，可用 story_groups 增删），主表与「排名最靠前的10条」每簇各保留 1 条代表条，其余完整内容进附录 17「议题簇合并留痕」；「窗口内全部数据」为筛选前候选池，不参与议题簇合并，被合并的各侧面全部保留、不删不改。**议题层不参与 cross_score**，不把多家媒体报道同一冲突虚增成同一事件的多渠道热度。
- 议题判定：主体词只认标题（汇总稿与陈年存档稿摘要常夹带国名，允许摘要命中主体会把不相干稿件拉进簇），动作词可来自标题或摘要；至少命中 1 个主体词、且主体与动作合计命中 ≥2 个不同词才归簇。代表条优先取簇内 Final_adj 最高者（该议题最突出的一条），其次按标题命中主体词数，不按摘要长度选；代表条「内容摘要」保持原文，不把被合并条内容塞进该列；展示序由编排层在去重后重算。开关 story_dedup（默认 true，设 false 关整层）、story_max_keep（默认 1，设 2 可留两条不同侧面）、story_groups 自定义词组表。附录 17 逐条列议题名、代表条、被合并条标题与来源、摘要首段、命中主体与动作词组，完整内容不删除、不静默消失；删行后「排名最靠前的10条」须补足 10 行且与主表前 10 行逐格一致，窗口内全部数据 ⊇ 主表 ⊇ 前 10 仍成立（候选池为筛选前全量）。口径表写「议题簇去重」项，报告合并条数与议题簇数。

四、打分（数值不可为编排结果改动）
- 信息功能档位 I/C 单条取最高一档、不叠加：I +9/+7/+5/+5/+5/+4/+4/+1/0（重大伤亡 / 权威预警 / 终局性新规 / 国家级响应 / 重大司法终局 / 重大数据 / 科技工程突破 / 消费警示 / 便民提示），I_base=5（含明确受影响对象）否则 3，I=min(20,I_base+I_func)；C +3/+2/+1（全国性 / 区域性 / 本地性），C=min(10,1+C_func)；单条封顶 I+9、C+3。逐条打印命中词组复核表，禁用泛词裸词，不按类目名称加分。已在准入剔除的条目不进打分；「重大数据」「科技工程突破」若属成就宣传或远期规划稿件，按三类强剔除先行剔除。
- T 为当日清单内「发布时间距采集窗口中点小时差」样本自适应百分位（最近→25，最旧→0），禁止 has_update 系数；pub 缺失取批内已知时刻年龄中位数。
- V=(0.24T+0.18I+0.14A+0.10C+0.06M+0.10V核实)/0.82×5；质量惩罚（旧闻 −8 / 标题正文失配 −5 / 仅自媒体 −5 / 无新事实 −4 / 无更新时间 −3）与三态核实（部分核实封顶 C、未核实不得进 A 级）。
- H 通道：>70% 条目无平台后台阅读 / 播放 / 讨论数时，P/H 一律置 NULL，Final = V/82.32×100，口径声明「H 通道关闭、Final 仅反映价值分 V」，并说明娱乐 / 赛事系统性偏低属数据缺口而非重要性判断；严禁构造虚假 H、不补零、不二次归一化、不把多渠道说成实测热度。
- 等级按原始 Final 机械映射：S≥85 / A 70–84.9 / B 55–69.9 / C 40–54.9 / D<40；S 可为空、不凑档位；D 如实标注、不作准入剔除。
- gin 按上位大类内 Final 降序、按事件主键去重计数；cap 由信息功能档位触发（4/3/2），λ=6，Final_adj = Final − 6×min(gin−1, cap)；展示分可为负、不加下限、不手工挪位次。用户未指定条数则不设上限，指定时按保护截断（protected = 命中重大伤亡 / 终局性新规 / 权威预警 / 重大司法终局 OR 原始 Final≥70，加大类覆盖保底）并做反事实验证。

五、编排（只改展示序，不改 Final / Final_adj / 等级 / gin / cap / V / I / C 任何数值）
- U = daily_score（表 R 八组：天气与出行 / 物价与消费 / 房价与居住 / 工作与收入与社保 / 医药与医保 / 产业与就业（工厂、制药、AI 发展、新能源、裁员、企业倒闭与债务、地方政府负债）/ 社会议题 / 公共服务，min(12,4×命中不同组数 + min(4,命中词组总数))）+ cross_score + 8×clip(Final_adj/批内最大,0,1) + 重要国际动态加权 6 + 可配标签加权。天气不硬置顶，作为高相关组之一自然靠前；贴近日常且影响人群越广的条目自然靠前。
- 头部三席独立判定：资格池 = cross_score>0 且 daily_score>0（多渠道 + 日常相关，池不足 3 条才放宽并声明）；head_score = 1.8×daily_score + 1.5×cross_score + 6×clip(Final_adj/批内最大,0,1)，头部不给重要国际动态额外加权；逐槽在「上位大类 ≠ 上一条」候选里取最高，头部不参与覆盖保底换出，头部末条大类与标签传给前窗打散。第 4 位起沿用编排。
- 前窗 10 条：front_cap 必须扣减头部占席；同一上位大类最多 3 条（重要国际动态名额 4），前窗内同一六类标签最多 1 条；未被覆盖但有准入条目的大类做覆盖保底换入并逐条留痕；容量不足时上限放宽并如实声明，不编造凑数。覆盖统计必须含头部三席。
- 相邻同类打散：在 U 降序序列上贪心交错，前窗相邻同大类必须为 0；主键上位大类、次级分类标签（国际动态用六类标签，其余用细标签，U 差 ≤1.0 时优先错开）；front→tail 边界传递大类与标签；容量不足被迫连续同类须逐条列位置、大类、标签与原因。
- 编排留痕（附录 11）、头部留痕（附录 16）、打散对照（附录 14）逐条列 U 降序位 → 展示序、日常组、独立渠道数、cross_score、U、Final_adj 与动作；orchestrate=false 回纯 Final_adj 降序，head_window=0 / interleave=false 可关，所用开关取值写进口径说明。展示序与 Final_adj 严格降序不一致须如实标注，不得包装成公式结果。

六、展示与交付
- 三张数据表统一 **12 列**且列名列序一致：展示序 / Final_adj / 等级 / 原始 Final / 分数序 / 上位大类 / 分类标签 / 标题 / 内容摘要 / 来源 / 事件主键 / 记录类型。**无关键词列、无重点句列、无原文图片列**。
- 第 10 列「来源」统一为 `渠道 · 渠道 · 渠道`，只列平台 / 媒体名；渠道间用带空格 ` · `，平台内部层级用不带空格 `·`（如 `微信·搜一搜·搜索发现`）；不编号、不用竖线、不带链接、不带占位、不写括注、不追加重复计数标记。三张表来源列格式一致。
