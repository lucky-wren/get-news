## 0. 使用说明与口径

### 0.1 什么叫「全渠道」

不是「来源列里出现过的平台名去重后的数量」，而是三层能力同时成立：

| 层 | 内容 | 判定标准 |
|---|---|---|
| 1 渠道白名单 | 固定一份按行业/形态分组的信源清单 | 本文档 §1–§31 |
| 2 每渠道采集器 | 每类源有对应拉取方式（RSS / 官方 API / 榜单四时点快照 / 站内时间倒排 / 公告列表 / 交易所披露） | §31 与 §34 |
| 3 窗口枚举与留痕 | 按窗口时间倒排扫完，逐条记发布时间与依据，逐渠道申报状态 | §34 / §35 |

三层缺一层，条数就会随「当轮想到几个关键词」浮动，不能称为全渠道。

### 0.2 窗口内全部数据的定义

第三张表 = 采集窗口内、**标题 / 摘要 / 来源三字段齐备**且**上位大类与分类标签合规**的**未经筛选处理**数据。只做窗口过滤与字段校验，不施加贴近度筛选、三类强剔除、国际门禁、同事件合并、议题簇合并、展示编排。评级列一律置「—」，展示序为采集序，其余字段沿用采集台账原值。主表是它的子集。

`✗` 级渠道命中且三字段齐备的条目同样入池（作为词条/线索留痕），不直接成为主表行。`✗` 表示需回查，不表示排除。

### 0.3 字段契约（每条 11 项）

| 字段 | 说明 |
|---|---|
| 标题 | 原文标题，去 SEO 尾巴 / 栏目前缀 / 站点分隔符 |
| 摘要 | 引用采集内容形成的完整表述，2–3 段、每段 2 全角空格缩进、净字数 ≤240、整句收束 |
| 来源 | `渠道 · 渠道`，不带编号 / 竖线 / 链接 / `等N家`；平台内部层级用不带空格的 `·` |
| URL | 可点开的独立原文地址；词条行填榜单快照页地址并标形态 |
| 发布时间 | `pubDate` / `datePublished` / 正文标准新闻时间戳 / 电头 / 外部注入 `pub`；取不到写字面值「未取得」 |
| 时间依据 | 上述值从哪来；未取得时写明「近一天收录仅保证抓取窗口」 |
| 时效标记 | 窗口内实证 / 正文日期推定 / 近一天推定 / 当日速览推定 / 往期日期线索·需核对 |
| 日期线索 | 标题与摘要里的月日串，只留痕，不冒充发布时间 |
| 上位大类 | 见 §33 分类表 |
| 证据等级 | A 独立原文 / B 聚合页拆出需回查 / C 仅话题名 |
| 去重主键 | 采集层完全重复用 `URL+标题`；事件层合并用事件主键，仅在编排阶段生效 |

### 0.4 时间字段优先级

`pubDate/datePublished` > 正文标准新闻时间戳（如「11月17日 14:20:34」） > 电头（「新华社11月17日电」） > 站点上线时刻（标「时点推定」） > 相对时间（「16 hours ago」，标「近一天推定」） > 未取得。

标题里的月日（如「11月26日调价」）是**事件日期或未来窗口**，只作日期线索留痕，**不得**当成发布时间。搜索引擎按当日词面重新收录的往年旧页，必须按原发布年份剔除并留痕。

### 0.5 给其他 AI 的最短接入

1. 把 §1–§31 当渠道白名单，先建「逐渠道状态申报表」（§35）再开始采；
2. 每轮按 §34 的四时点拉榜单、按窗口倒排拉时间流与公告列表；
3. 每条填写 §0.3 的 11 项字段，先出候选池，再按 §32 出主表；
4. 交付按 §32.9 的置顶池与影响面编排，五工作表、12 列、附录 1–17 + 候选池边界留痕；
5. 冲突时以 §32 规则为准，§36 的禁止项逐条自检。

### 29.1 词条成稿链路（硬性）

1. 抓榜单快照，记录**快照时刻**、榜单名、词条名、热度值、榜位；
2. 用词条 + 日期检索**独立原文**（央媒 / 部委 / 交易所 / 地方政务 / 主流媒体）；
3. 拿到带事实（时间、地点、主体、数字、处置）的原文，才允许写成事件概述进主表，来源列标 `微博·热搜 · 百度·热搜 · 央视新闻` 这类真实组合；
4. 片段只是热度值、榜单罗列或纯话题名 → `has_event=false`，**进附录 15 留痕，不进主表**；
5. 模型不许凭话题名猜内容；输出里出现片段外数字即丢弃，回退抽取式。

## 32. 采集与过滤规则

### 32.1 窗口与三层能力
窗口 `(前一日 20:00, 当日 20:00]`，左开右闭。按 §0.1 三层能力执行：白名单 → 每渠道采集器 → 窗口枚举 + 逐渠道状态申报（§35）。

### 32.2 级别口径
`★` 每轮必拉、按窗口枚举；`☆` 命中即采、用于回查与补渠道；`✗` 热度参考·需回查，词条/榜单形态回查到带事实独立原文才成稿，回查不到进附录 15。**任何级别命中且三字段齐备的条目都进候选池**。

### 32.3 每轮必采源清单
央媒总纲（§1）、部委总表（§3）、交易所与破产披露（§4–§5）、4 个热榜聚合页 + 3 份 60 秒早报（§28/§30）、澎湃/财联社快讯时间倒排流（§28）、微博/百度/抖音/头条四时点快照（§29）、中央气象台与 12379（§17）、USGS 与 GDACS（§17/§31）、新闻联播文字版（超右界留痕）。

### 32.4 采集时序
02:00 / 10:00 / 13:00 / 20:00 四次榜单快照 → 全天按窗口倒排扫时间流与公告列表 → 20:00 收口 → 逐条回查 → 出候选池 → 编排主表。

### 32.5 字段与时间
每条填写 §0.3 的 11 项；时间按 §0.4 优先级。标题里的未来月日只作日期线索；往年旧页按原发布年份剔除留痕。

### 32.6 同事件处理
候选池里同事件多渠道**各留一行、不做主表式合并与来源择一**；主表按事件主键合并并计渠道数。独立信源 ≥5 家且通过贴近度准入的事件进「多渠道高覆盖池」。

### 32.7 大众贴近度准入与三类强剔除
**正面清单**：衣食住行与物价、工作就业（裁员/欠薪/工时）、医保社保、工厂与制造业、制药与医药、AI 发展、新能源、地方政府负债、房地产、企业倒闭与资不抵债、社会议题；重大天气预警、全国性公共安全事件、现象级文娱与全国性赛事结果、涉及大范围人群的价格或政策变动。

**三类强剔除**：① 成就宣传与态势综述（「稳中向好」「同比增长」「再创新高」「成效显著」主导且无具体受影响对象与可行动项）；② 远期规划与未落地（拟建、规划中、征求意见稿、框架协议、意向签约、多年后目标、展望前瞻）；③ 与普通人无关的机构动态（会见出席、会务预热、人事任免、外事礼宾、内部评优、行业年会、纯政策解读）。

**国际门禁**：只留战争与武装冲突、灾害与公共卫生、突发事故与重大安全事件三类；重大突破、选举换政、国际形势、中性国际资讯剔；直接波及境内普通人切身利益的按民生条目保留并标注。

**企业规模闸**：破产/倒闭只留上市公司（交易所公告/股票代码）、全国性知名或行业头部、规模可核对的大型主体；地方小微、个体户、仅法院例行文书且无规模字段的剔。规模只认原文可核对字段。

**防误伤**：剔除看稿件性质，不看发布主体；机构名不得单独当删除开关。油价调整、气象预警、医保目录、社保办理、供暖退费、疫苗、限行、放假安排一律保留并归入正面清单。

### 32.8 置顶池与覆盖影响面
- 特别严重突发池：震级 ≥7.0 或权威定级强震、死亡 ≥10 人或伤亡 ≥30 人、国家级应急响应、跨省及以上红/橙预警、大范围灾害或重大公共卫生事件。阈值须与独立原文一致，多来源冲突并列标注取可核对的最高值，不推测凑数。
- 多渠道高覆盖池：独立信源 ≥5 家且通过贴近度准入。
- 严重突发池优先；池内按 `impact_score` → 伤亡/震级量级 → 渠道数 → `head_score` 排。两池皆空才回退原头部三席并声明「本批无置顶池命中」。第 1 位不参与「大类 ≠ 上一条」约束，第 2 位起仍要错开。
- `impact_score = min(12, 人群范围×1.5 + 地域范围 + 紧迫与严重×1.5 + 可行动性)`，四维逐条留痕，只进 `U` 与 `head_score`；`Final` / `Final_adj` / 等级 / gin / cap / V / I / C 数值一律不动。

### 32.9 交付契约
五工作表、12 列；主表 / 前 10 表 / 窗口内全部数据（候选池）三表表头一致，前 10 表与主表前 10 逐格一致；主表是候选池子集且非评级列逐格一致；来源 `渠道 · 渠道`；摘要 2–3 段、每段 2 全角空格、净字数 ≤240、整句收束；附录 1–17 齐全另带候选池边界留痕与逐条时间留痕。

### 32.10 状态申报
每轮按 §35 逐渠道写：命中与否、拿到什么形态（独立原文 / 聚合页 / 词条 / 公告 / 时间流）、能否按窗口枚举全量、缺口与原因。没拿到的如实写「未取得」，不假装有数据。

## 36. 禁止项（18 条）

1. 不把标题里的未来月日（如 11-26 调价）当成发布时间。
2. 不把搜索引擎重新收录的往年旧页当成当日新闻。
3. 不用「发布主体是政府/机构」当删除开关；只按稿件性质判。
4. 不把采集工具名（`Tavily 检索结果`、`serper`）写进来源列当渠道。
5. 不把 `Com` / `Gov` / 英文 slug 之类无意义串编造成渠道名。
6. 不把聚合页 / 60 秒早报整页当拼盘母行剔除；必须全量拆条。
7. 不凭热榜话题名扩写事件；必须先回查到带事实独立原文。
8. 不让模型凭空新增数字、事实、URL、占位句；输出数字须可在原文锚定。
9. 不在候选池做贴近度筛选、同事件合并、议题簇合并或展示编排。
10. 不把候选池做成主表的逐格复制；评级列必须全「—」、展示序为采集序。
11. 不把「未取得发布时间」写成抓取时刻或窗口起点。
12. 不因 `status` 之类链路字段把会话内批次标成降级；两条链路的状态字段互不混用。
13. 不把「检索请求成功数」当成「有效独立信源数」。
14. 不把来源列里出现过的平台名数量当成全渠道数。
15. 不为凑条数回放既有台账或换文件名重出一份更「多」的表。
16. 不把 `✗` 理解成不入池；词条留痕是候选池的一部分。
17. 不在多来源口径冲突时私自择一或推测凑整（震级、伤亡、清偿率并列标注）。
18. 不假装有数据：拿不到的渠道逐条申报「未取得」，不编造渠道与条数。
