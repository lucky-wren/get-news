# 每日要闻筛选 · 评级技能

> 一句话：**把「一堆条目」变成「一份能直接读、能照着做、能回查来源」的日报**。
> 本技能只定义业务判断标准与产出规范，不绑定任何平台、账号或数据源；不负责产出某份具体清单的结果。

---

## 0. 定位

**解决**

- 条目几十到几百条、来源混杂（部委官网、门户、社交热榜、问答社区）时的取舍
- 「要重要的」「跟日常相关的」「别给我遥远的政策」这类优先级判断
- 同一事件多来源重复、标题党与真实事件混杂、榜单词查不到原文
- 需要「标题 + 内容摘要」而不是标题清单，且每条能回查来源
- 需要可复用、可交接、可质检的稳定产出格式
- 大批量剔除与普通人日常生活无关的纯政务内容，且不误伤部委发布的日常可行动信息（油价、预警、社保、召回、反诈、考务等）

**不解决**

- 不代替用户判断立场或做观点评论
- 不生成预测、荐股、投注建议
- 不把查不到原文的条目补全成看起来完整的摘要
- 不做长篇深度研究报告

## 1. 输入与输出契约

### 1.1 输入

| 字段 | 说明 |
|---|---|
| 清单 | 编号条目，含「标题 / 来源或 URL / 类别」，可能带日期与总数 |
| 用户口径 | 优先级偏好、必收栏目、少放题材、条数上限（可「不设限」）、交付格式 |
| 日期与窗口 | 以清单日期或用户指定日期为准，全文统一；滚动窗口默认 `(前一晚 20:00, 当晚 20:00]` 左开右闭 |
| 平台数据 | 可取得的阅读 / 播放 / 搜索 / 讨论 / 互动与位次；允许缺失，缺失须显式标注 |

### 1.2 输出

| 字段 | 说明 |
|---|---|
| 结构化文档 | Markdown（默认）；用户指定其他格式时按指定格式 |
| 表格交付 | 三张数据表统一 **12 列**，列名与列序一致；五工作表结构见 1.4 |
| 每条必备 | 等级、标题、内容摘要、展示分 `Final_adj`、原始 `Final`、分数序位次、`gin` / `cap` / 递减量、上位大类、`H`（含压缩值）、`V`（含 I/C）、传播信号构成、原清单编号、分类标签、核实状态；命中信息功能档位的条目另标 `ΔI/ΔC/ΔFinal` |
| 全文必备 | 目录、口径说明、用户口径 → 落地方式转换表、日常相关性逐条判定表与剔除留痕、大类级准入逐条判定表、国际资讯逐条处置表、渠道覆盖表、窗口外排除清单、排名总表、分数分布、筛选说明、信息功能档位赋值留痕表（含逐条命中的最高档位与实际 ΔI/ΔC）、编号唯一归属冲突表、大类映射表 / 覆盖对比 / cap×λ 参数对照 / 完整位移对照 / 大类规模偏差诊断表、编排留痕、头部三席留痕、摘要来源留痕、来源索引、生成时间与条数 |
| 指定条数时另需 | 保护集合名单、反事实验证、被截条目逐条核验表、打散位次损失表 |
| 可选 | 合并对照表、回测登记 |

### 1.3 表格字段契约（12 列）

| 列 | 字段 | 说明 |
|---:|---|---|
| 1 | 展示序 | 编排后的阅读顺序 |
| 2 | Final_adj | 展示分，排序主键 |
| 3 | 等级 | 按原始 `Final` 机械映射 |
| 4 | 原始 Final | 合成判断分 |
| 5 | 分数序 | 纯 `Final_adj` 基准序 |
| 6 | 上位大类 | 8 类之一 |
| 7 | 分类标签 | 细标签；国际动态用三类重大突发标签 |
| 8 | 标题 | 识别用，不改变事实 |
| 9 | 内容摘要 | 取原文全文，仅 >240 字才精简；2–3 自然段，段间 LF，每段首行缩进 2 个全角空格；见 §8 |
| 10 | 来源 | `渠道 · 渠道 · 渠道`：只列可核对的平台 / 媒体名；渠道间用带空格 ` · `，平台内部层级用不带空格 `·`（如 `微信·搜一搜·搜索发现`）；不编号、不用竖线、不带链接、不带占位、不写括注、不追加重复计数标记 |
| 11 | 事件主键 | 聚类后的统一 eid |
| 12 | 记录类型 | 主条 / 拆出词条 / 渠道明细等 |

**不设关键词列、不设重点句列、不设原文图片列。**第 9 列只放摘要正文，不含任何标签、分隔符（`｜`、`【`、`】`）或占位句。解析端零正则：按 `\n` 切段、trim 掉缩进即为段落数组；`wrap_text` 开启、列宽 60、第 9 列表头批注写明列契约。未用富文本与合并单元格，保证 xlsx → CSV / JSON 无损。

### 1.4 五工作表

| 序 | 工作表 | 内容 |
|---:|---|---|
| 1 | 处理后的数据 | 主表：全部独立事件，按展示序 |
| 2 | 排名最靠前的10条 | 主表前 10，逐格与主表一致 |
| 3 | 窗口内全部数据 | 筛选前采集候选池：三字段齐备、分类合规、未经筛选与合并，评级列置「—」，展示序为采集序 |
| 4 | 口径与稿外信息 | 口径正文 + 附录 1–16 |
| 5 | 评级留痕 | 15 列，逐条覆盖主表台账的评分输入与判定 |

**主表与「排名最靠前的10条」按事件主键去重**：完全重复行必须为 0；「窗口内全部数据」为筛选前候选池，只去采集层完全重复行、不去重不合并。被合并的渠道记录不删除，逐条列入附录 12b。

**同一议题下的不同侧面按议题簇去重**：每簇在三张表里各保留 1 条代表条，其余完整内容列入附录 17，不静默消失。议题层不参与多渠道重复度计数。

### 1.5 默认口径

- 条数：不设限，但不因凑数降低质量。
- 排序主键：`Final_adj` 降序（`Final − λ×min(gin−1, cap)`，热度 26.2% + 价值 73.8%）；默认 λ=6，λ=0 退回纯 `Final` 降序。
- 启用编排层时，展示序由编排分 U 决定（见 §4.9–4.12），但 `Final` / `Final_adj` / 等级 / gin / cap / V / I / C 数值一律不改。
- 必收校验（仅核对是否漏收，不写入排序）：诈骗与安全预警、出行与天气、健康与用药、劳动与社保权益、物价与市场、重大突发、重大突破、重要赛事、热门娱乐、发展产业资讯。启用大类级准入清空某类时，该类同步移出校验清单。
- 排除：主观整类降权；条目不合格靠字段与核实态自然落位。
- 大众贴近度准入（§4.1.3）默认启用，严格度默认 `strict`，可切 `moderate` / `off`，所用档位必须写进口径说明；目标读者为普通大众，只收与日常生活和切身利益贴近的资讯。
- 天气硬锚点默认关闭（`weather_first=false`）；天气作为表 R「天气与出行」高相关组之一自然靠前，不独占第 1。

## 2. 三条铁律

1. **先判断「跟谁有关」，再判断「有多重要」**。一条影响上亿人下周买票的新闻，优先级高于措辞宏大但落地在 2030 年的规划。
2. **事实强度优先于流量奖励**。热度只占 18% 权重；查不到原文就没有摘要，绝不靠常识脑补数字、比分、金额、结论。
3. **评分层、准入层、编排层三者分离**。「赛事只留两条」「少放国际」属于准入 / 条数口径，单独记录、不写进公式；「日常相关靠前」「不同标签都要有」属于编排层，只改展示序。三者都不允许手工挪动某条的评分数值，否则回测分不清是规则有效还是人工干预。

## 3. 信源渠道清单

### 3.1 覆盖要求

必须按 8 个上位大类逐组采集，覆盖所有可用渠道后，再对结果统一执行准入判定。**准入只在采集后执行**：禁止在采集阶段按题材或大类框定检索范围，禁止因用户口径跳过大类。某大类准入后 0 条须逐渠道申报「已触达 / 未触达 / 按准入剔除」，不得静默不采、不得编造条目凑数。渠道逐条状态写入附录 3。

### 3.2 平台渠道

| 渠道 ID | 名称 | 采集方式 | 独立信源归一 |
|---|---|---|---|
| D01 | 抖音·热点 | 搜索 API `site:douyin.com <关键词>` | **抖音** |
| W01 | 微博·热搜 | 搜索 API `site:weibo.com <关键词>` | **微博** |
| X01 | 微信·公众号 | 搜索 API `site:mp.weixin.qq.com <关键词>` | **微信** |
| X02 | 微信·搜一搜·搜索发现 | 搜索发现词条，**每条须回查独立原文后成行** | **微信** |

- 三个平台均无公开 RSS、无免鉴权热榜接口；无 `SERPER_API_KEY` 时逐渠道写明「未触达：需配置 key 走 site: 定向检索」，不得假装抓到、不得编造条目。
- 来源统一写作「抖音·」「微博·」「微信·」，归一为三个独立渠道参与 `cross_score`；同一平台多个账号仍算 1 个独立渠道。
- 平台后台播放 / 阅读 / 讨论数拿不到时，**H 通道保持关闭**；三平台只作为独立信源计入多渠道重复度，不冒充实测热度。
- 经 `_inbox.json` 注入的检索结果，须在口径说明标注「外部注入」，与附录 3 的适配器触达状态分开陈述。
- `adapters.platforms: true` 开启平台采集。

### 3.3 独立原文准入

每条成行数据必须有可点开的独立原文 URL。

- 社交平台热榜**不能只写话题名 + 热度值**：须回查独立原文，把事件概述（谁 / 何时 / 何地 / 数字 / 发生了什么 / 可行动项）写进摘要。
- 只有话题名 + 热度、查不到事件正文的词条，按独立原文准入剔除，并在附录留痕；不拿热度值凑数。
- 微信「搜一搜·搜索发现」词条只是话题发现入口，逐条回查后才成行。
- 纯部委频道入口（官网首页、栏目页）、索引页、目录线索无事件无原文 → 标「未核实」→ 观察池，只留标题。

### 3.4 多事件拼盘稿：拆分优先

一条罗列稿 = 主体事件 + N 个同榜词条，每一条都是独立资讯。

| 情形 | 处理 |
|---|---|
| 首段为列举导语（`资讯早餐…列出` / `体育要闻:` / `文娱影视:` / `今日头三条…` / `赛果:` / `三条分别为`…） | **主体事件必留**，只裁掉罗列尾巴 |
| 尾部写「同榜还有…」「另有…」「同日还报…」 | 裁掉尾巴，只留主体事件；尾巴里的每个词条拆成独立候选行 |
| 拆出的词条 | 逐条回查独立原文后成行；未取得原文的进附录 15「线索待原文」留痕，不静默消失 |
| 标题本身是汇编名（「资讯早餐列今日…」「聚合日报」）、抽不出单一事件主体 | 剔母行，但把它列出的词条全拆出来 |
| 叙述性尾巴（援引 / 报道称 / 提振 / 维持在 / 跌幅 / 收于 / 同比 / 预计） | 不切成假词条，它只是主体事件的补充数据 |

裁剪必须回退到上一个完整句末，不留半句。拆分器剔除热度值（`733万`）、话题号与叙述碎片。被剔稿件一条不删，全进附录 15 逐条留痕。

## 4. 评级模型（筛选 → 权重 → 打分 → 排序编排 → 截断）

### 4.1 筛选与准入

筛选按**字段不合格 → 核实态 → 自然低分**执行，不按题材先验淘汰。社会 / 文娱 / 垂直均有约三成上榜机会，不支持按类别一刀切。

| 清单条目类型 | 处理方式 |
|---|---|
| 有事件、有权威原文 | 正常进入打分 |
| 纯部委频道入口 | 无事件、无原文 → 标「未核实」→ 观察池，只留标题 |
| 纯会议 / 会见 / 表态 | `C` 公共价值低、`A` 低 → 自然低分；无新事实再扣 −4 |
| 远期规划 / 成就宣传 / 无关机构动态 | 走 §4.1.3 三类强剔除；含「已生效 / 即时可办理」字段者保留 |
| 无可核实原文的榜单词 | 三态核实「未核实」→ 封顶、只留标题 |
| 已被其他条目覆盖的索引型条目 | 按事件主键合并 |

执行顺序：大类级准入 → 大众贴近度准入 → 国际动态仅重大突发限定 → 低价值过滤 F 层 → 打分。准入层只决定「收不收」，不进六维价值分、不改等级、不改任何条目位次，也不引用分类标签或信息功能档位。被剔条目不参与 `gin` / `Final_adj` / 截断，也不参与覆盖保底；逐条留痕、不删不改。

#### 4.1.1 大类级准入

```
EXCLUDED_GROUPS = 用户明确要清空的上位大类        # 该大类全部剔除
GATED_GROUPS    = 用户说「除非特别重要」的大类    # 仅留命中「特别重要」事实字段者
excluded = 大类 ∈ EXCLUDED_GROUPS
           OR (大类 ∈ GATED_GROUPS AND NOT 命中「特别重要」事实字段)
```

**「特别重要」事实字段 `major_intl`**（可由用户口径替换）：`台湾代表处`、`涉台`、`中国使馆`、`强闯…使馆`、`中国领空`、`中国领海`、`侵犯我国`、`涉我`。禁用裸「主权」「领土」——它们常只是谈判议题词。

六条硬约束：

1. 「特别重要」必须是全局可核对词组表，任何条目命中即留；禁止用「重大」「重要」「影响大」主观词，禁止编辑逐条挑。
2. 泛词必须全表验证：裸「主权」「领土」「就医」「住院」「失业」「工资」「物价」「分别」「部署」「发文」「突破」都会误命中。一律用词组匹配，改完打印逐条命中表并写明命中总数。
3. 交付物给「逐条判定表」：GATED_GROUPS 里每条列「保留 / 删除 + 判定依据」；写明「若你认为某条也算特别重要，一句话恢复」的开关；用户点名的条目标 ★。
4. 被删条目逐条留痕（原展示序、大类、剔除原因、标题）；重复粘贴的同一标题按同一条处理。
5. 被删条目不参与 `gin` / `Final_adj` / 截断，也不参与覆盖保底，否则等于没删。
6. `must_include` 同步移出；覆盖按「未剔除大类」口径报告，如实写明「某大类 0 条是准入结果，不是漏收」。

#### 4.1.2 国际动态仅重大突发准入

**国际动态只保留三类重大突发事件**并标 `intl_important`：**战争与武装冲突 / 灾害与公共卫生 / 突发事故与重大安全事件**。全部由可核对词组表判定（沿用表 G-重要中这三类词组），禁用「重大 / 重要 / 影响大」主观词，禁止编辑逐条挑。

| 三类 | 词组（节选） |
|---|---|
| 战争与武装冲突 | 发动空袭、弹道导弹、无人机袭击、打击美军基地、停火协议破裂、撤军、胡塞武装、霍尔木兹海峡已被封锁、油轮触雷、阵亡、军事侵略 |
| 灾害与公共卫生 | 级地震、震级调整、强震、海啸、洪灾、飓风、火山喷发、埃博拉、霍乱、疫情仍未得到控制、冰冻圈加速退化 |
| 突发事故与重大安全事件 | 全国停飞、停飞令、数千架次航班、机场关闭、空难、坠机、剧烈爆炸、核泄漏、恐袭、火箭未能送入预定轨道、大规模停电 |

**「重大突破 / 选举换政 / 国际形势」、表 G-中性**（自贸区 / 议定书 / 国际标准 / 汇率 / 全球机构等）、**表 G⁻ 低重要度、其余中性国际资讯一律剔除**并逐条留痕。

**唯一例外**：该事件直接波及境内普通人切身利益（跨境航班大面积取消、进口药断供、境外重大灾害涉中国公民、跨境价格或供应突变）时，按民生条目保留并标注依据，不标 `intl_important`。

**`INTL_GEO_SIGNAL` 境外主体信号前置**：命中明确国家 / 地区 / 组织名优先归「国际动态」，分类只作元数据。

### 4.3 传播足迹分 H 与诚实降级

```
platforms   = 该事件登上的、有实时榜数据的平台数
board_slots = 这些平台上的热榜词条个数（同事件多编号 = 破圈证据，加分而非被合并掉）
media_slots = 有具体文章 URL 的新闻源条目数
P = min(20, 5×platforms + 1×(board_slots − platforms) + 3×min(media_slots, 2) + 1 if media_slots>0)
H = P × 5                      # 传播足迹分 0—100
```

**硬约束**

1. **编号唯一归属**：同一清单编号被多条主条引用时只能归属一条；打包词条级条目不认领榜单信号，其编号归并到对应事件主条；冲突明细在附录留痕。
2. **同事件合并后 `H` 取峰值、不累加**：主条传播信号取各合并条中最大值，不把花絮的 `H` 加上去；保留全部原编号并写明取舍。
3. **标注「暂无公开实时榜数据」按未监测处理**：不计信号，也不当零热度；部委官网入口页、索引页不计入 `media_slots`。
4. `H` 是传播足迹的**代理变量，不是真实浏览量 / 讨论量**。
5. **诚实降级**：清单中 >70% 条目没有平台后台数据（只有新闻源 URL、无播放 / 阅读 / 讨论数）时，`P` 与 `H` 统一置 **NULL**，`Final = V/82.32 × 100`。文档必须声明「本批无平台后台数据，H 通道关闭，Final 仅反映价值分 V」。**不得**用可数信号构造出虚假 `H` 参与合成，也不得把多渠道重复度说成实测热度。
6. 编号唯一归属、取峰值、未监测三条照旧执行，不因 `H` 置 NULL 而省略。要真正确证，须接入平台原始值并按「同一平台—同一日—同一指标」百分位化后算 `P`。

### 4.4 信息功能档位（I / C 赋值）

**核心原则：不按类目加成分档，按信息对读者的功能角色分档。**`I` 与 `C` 的加分不引用任何类目名称，只识别信息本身的功能特征，各类目都有机会拿到高分。

```
I_base = 5  若文本含明确受影响对象（中国/国内/全国/车主/旅客/消费者/患者/学生/
             市民/投资者/市场/居民/劳动者…），否则 3
I = min(20, I_base + I_func)     # I_func 为该条命中的最高一档
C = min(10, 1 + C_func)          # C_func 为该条命中的最高一档
★ 单条只取最高一档，不叠加、不累加
T / A / M / V(核实度) 按 4.2 分档赋值
```

**正则约束（逐条适用）**

- 全部标签用词 / 词组匹配，禁用泛词。典型误命中：裸「别」命中「分别拿下影帝」、裸「清单」命中「基础清单」、裸「突破」命中「难有实质突破」、裸「发文」命中社交帖文、「部署」命中军事部署、「施行」命中「未施行」。

- 新规必须是正式制度文本；领导讲话、表态、记者会问答不算。
- 预警必须有行动指令；只说「未来有雨」不算预警。

**四条硬约束**

1. **只加分、不按题材减分**：娱乐、国际、赛事的低位次来自「缺少正向功能档位 + `I_base` 落 3」，不是因为它们属于某类。`I/C` 加分不得引用类目名称。
2. **单条取最高一档、不叠加**：一条同时命中两档，只算最高档，保证任何条目的最高分有明确上限。
3. **用户口径的转换表写进交付物**：把「去掉哪条 / 合并哪几条 / 某类上调 / 某类下调」逐项列成「用户口径 → 落地方式 → 性质（准入层 / 编排层 / 全局规则）」对照表，可回查、可复现。
4. **补实摘要不改分**：联网用权威原文补齐的条目，摘要与核实态可更新，但不回溯修改 `I/C/V/Final` 基准，否则破坏跨批可比性。多来源口径冲突并列标注、不私自择一。

### 4.5 Final 合成、时效与等级映射

```
# 通道一：价值分 V（重要性，六维）
Raw6 = (0.24T + 0.18I + 0.14A + 0.10C + 0.06M + 0.10V) / 0.82
V    = Raw6 × 5                                   # 实达上限 82.32

# 通道二：传播足迹分 H
H    = P × 5
H_c  = √(H / 100)                                 # 开方压缩，抑制头部幂律

# 合成：单一排序分
if H is NULL:                       # 清单无后台传播数据
    Final = V / 82.32 × 100         # 热度通道关闭，仅按价值分排序
else:
    Final = 100 × (0.262 × H_c + 0.738 × V / 82.32)
```

**T 的取值**：`T = 25 × 当日清单内「发布时间距采集窗口中点的小时差」百分位`（最近→25，最旧→0）。`pub` 缺失时按「时点推定」处理，取**批内已知时刻年龄的中位数**，不按当前时刻算 age=0 拿满时效分，也不补造具体时刻；推定条目逐条留痕。

`0.262` 来自「热搜热榜仅覆盖 26.2% 网民」；热榜是新闻入口之一，不是全部。平台自己已给热搜加「大众关注度 / 领域关注度 / 内容质量度」三维并日均剔除货不对板词条，价值维度必须占主导。开方压缩把 75 vs 20 的 3.75 倍差距压到约 1.94 倍，是样本不足时的稳健近似；严格解法是类内百分位归一化（同一题材内比相对热度再去基线），列为接入后台数据后的下一步。

**跨平台硬约束**：原始播放 / 搜索 / 讨论 / 阅读数永不直接相加；各平台先按「同一平台—同一日—同一指标」转百分位，跨平台只加百分位。

**尺度与诚实声明**：`Final` 是**合成判断分，不是实测值**；`H` 是**代理变量不是真实浏览量**；`W_H = 0.262` 是**审慎先验、非因果估计**，须用真实清单表现回测四周后微调。三者都必须在交付物开头写明，禁止二次归一化。

| 等级 | Final 区间 | 含义 |
|:---:|---:|---|
| **S 必读** | ≥85 | 既破圈又极重要（本清单可能为空） |
| **A 重要** | 70–84.9 | 重大突发、终局性新规、国家级预警、高价值治理 |
| **B 值得看** | 55–69.9 | 宏观数据、司法进展、科技突破、赛事、娱乐、消费警示 |
| **C 浏览** | 40–54.9 | 便民服务、生活提示、背景词条 |
| **D 不入选** | <40 | 信息量不足或未核实 |

S 档允许为空：若热度最高的条目价值一般、价值最高的条目无榜单信号，S 就是 0 条；不为凑档位下调门槛，在分数分布里写明原因。等级**按原始 `Final`** 机械映射，不随展示分变动；D 是打分结果而不是准入剔除对象，如实标注、不偷偷删条。

### 4.6 质量惩罚与核实三态

**不设类别加成**，类别信息只保留为标签，不进公式。

| 情形 | 扣分 |
|---|---:|
| 旧闻冒充新事 / 旧影像无标注 | −8 |
| 标题与正文在主体、时间、地点、结果、影响任一项失配 | −5 |
| 来源仅自媒体且无独立佐证 | −5 |
| 只有情绪或立场、无新事实 | −4 |
| 涉伤亡 / 事故 / 政策却无更新时间 | −3 |
| 疑似水军或异常数据 | `P` 置 NULL、进审查态 |

**三态核实**：已核实正常评分 → 部分核实进观察池、封顶 C → 未核实不得进 A 级，24 小时后仍无权威确认降 D。

### 4.7 排序主键：展示分 Final_adj

```
排序键 = (- Final_adj, - Final, 原清单编号)
Final_adj = Final − λ × min(gin − 1, cap)        # 默认 λ=6
gin  = 该条目在其上位大类内按 Final 降序的排名（头名 gin=1），按事件主键去重计数
cap  = 该条目命中的信息功能档位对应的 cap 值；同时命中多个档位取最高值
```

- 第一位且唯一实质依据为 `Final_adj` 降序；`-Final` 与原编号只是同分 tie-break。
- 最终是单一严格降序列表，无按分类的章节、分组、置顶、后置、折叠。
- 每条元信息行同时给出 `Final_adj`、`Final`、分数序位次、`gin`/`cap`/递减量、`H`（含压缩值）、`V`（含 I/C）、传播信号构成，原始分数序完整保留、可逐条复算。
- 等级按原始 `Final` 机械映射：打散只改阅读顺序，不改「这条重不重要」。

**cap 档位表（由信息功能档位触发，与类目无关）**

| cap | 触发档位 | 递减上限 |
|---:|---|---:|
| **4** | 终局性新规 / 重大伤亡 / 权威预警 / 重大数据 / 国家级响应 / 重大司法终局 | −4λ（约 −24） |
| **3** | 科技 / 工程突破 / 消费警示 | −3λ（约 −18） |
| **2** | 便民服务 / 生活提示（仅 C 维度有加分的条目） | −2λ（约 −12） |

同一信息功能在不同类目中触发相同 cap：「油价下调」属财经类命中「重大数据」→ cap=4；「流感高发」属民生类命中「权威预警」→ cap=4。

- 对全部大类一视同仁，是「同类重复出现的边际递减」，不是给某类加分或减分；每个大类的头名不扣分，各大类最高分条目自然齐聚前排。
- cap 封顶 4：同一大类第 5 条起不再追加扣分。
- `gin` 只依赖原始 `Final` 降序、`cap` 只依赖信息功能档位命中，两者可在渲染前一次算完；`Final_adj` 天然构成全局严格降序，只有一个序。同事件多渠道共享一个 `gin`，采集台账仍保留全部渠道记录。
- λ 可调，λ=0 即退回纯 `Final` 降序；交付物附 λ 敏感度表（0/3/4/5/6/8 的前 5/10/15 覆盖与平均位移）。

**排序原则**

1. 「日常相关」分两层：全国性 / 跨区域 / 带明确行动窗口的（天气出行、车票、社保、用药、物价房价、反诈）影响人口最广、错过窗口就没价值 → 最靠前；单篇生活科普虽也日常，影响面窄、可替代性强 → 不得与前者同级。
2. 突发 / 重大事件是例外通道，但不按题材开，靠信息功能档位自然上位。
3. 诊断顺序：先查 ① I/C 是否近封顶 ② `gin≥cap+1` 是否被递减锁死 ③ 该上位大类是不是条目最多的大类（大类规模偏差）。叠标签解决不了，调 λ 优先于新增特例。
4. 交叉度是结果而非目标：分类的作用是限定为对称打散维度，改变位置但不进六维价值分、不改变等级、不产生分组、不做类目配额。不得为达标而人为调整位次。
5. 复现不了就查信息功能档位命中、正则误命中、编号归属、大类映射与 λ，不许手工挪位次补救。

**锚点校准**：交付前用 5–7 个已知条目检验相对位次——重大伤亡 / 司法终局 / 终局性新规 / 权威预警应进前列；全国性数据发布应进中段以上；娱乐可因真实热度进中上段但不得占第 1；生活科普不得占前列；地方时令景观不得因全国性标签跟着上位；远期规划与纯词条垫底。前 10 覆盖 ≥5 个上位大类、前 15 覆盖全部大类、同一大类前 5 条原则上不超过 2 条，仅供参考，不足时如实写明代价。

### 4.10 头部三席独立判定

前 `head_window=3` 席由独立判定选出，覆盖保底与相邻打散不得挤占：最重要最突出的三条占据头部。

```
资格池 = cross_score > 0 且 daily_score > 0
         （多渠道重复率 + 与普通人日常相关；池不足 3 条才放宽到全池并声明 head_relaxed）
head_score = 1.8 × daily_score + 1.5 × cross_score
           + 6.0 × clip(Final_adj / 本批最大值, 0, 1)
           # 头部刻意不给国际重要动态额外加权
逐槽：在「上位大类 ≠ 上一条大类」的候选里取 head_score 最高者
      （head_interleave=false 则按纯 head_score 降序）
容量不足才允许被迫同类相邻，逐条留痕
头部不参与覆盖保底换出；头部末条的大类与标签传给前窗打散，保证 #3→#4 边界不堆同类
第 4 位起沿用既有编排
```

资格池只是**排序池，不是准入**：境外选举、重要国际动态仍在主表，只是不占前 3。头部相邻大类不同会让个别槽位的 head_score 出现小幅倒挂，这是打散代价，附录 16 逐条列 head_score、日常相关、跨渠道、基准分、U 降序位与相邻同类被迫情况。`head_window=0` 关闭该层。

### 4.11 同类上限与覆盖保底

```
front_cap = top_n − len(head3)              # 头部占席必须扣减
front_window = 10（可配），max_per_cat = 3（可配）
① 按 U 降序贪心填入前窗剩余席位，同一上位大类最多 max_per_cat 条
   （头部名额也计入同类上限）
② 未被覆盖但**有准入条目**的大类 → 从候补取该类 U 最高者，
   换掉前窗中「所属类 ≥2 条且 U 最低」的一条，逐条留痕
③ 容量检查：可用大类数 × max_per_cat < front_window 时上限自动放宽并如实声明，
   不编造条目凑数
```

覆盖统计必须包含头部三席（`covered_before = head3 + front`，`covered_after = ordered[:top_n]`），否则缺类误报、覆盖保底换入的条目会在打散后被挤出前 10。国际动态前窗名额 `intl_front_cap` 默认 4（其他大类 3），前窗内同一三类重大突发标签最多 1 条，让有限名额来自不同三类；设 3 即严格等额。

因准入门禁或 F4 导致可用类数下降，写明是**准入结果而非漏收**；前 N 覆盖大类数如实报告，低 `Final_adj` 条目被编排提前须在留痕表可查。

### 4.12 相邻同类打散

```
候选池 = 已按 U 降序的 front（前窗）/ tail（尾部）
for 每个位置:
    合格 = 上位大类 != 上一条大类的候选
    if 合格:
        取合格里 U 最高者；
        若它的「分类标签」与上一条相同，且存在 U 差 ≤ interleave_label_epsilon
        且标签不同的合格候选 → 改取后者（次级错开）
    else:
        容量不足（该大类条目数 > 其他类总和）：
        取剩余里「分类标签 != 上一条标签」且 U 最高者；
        仍无 → 取 U 最高者，标「被迫连续同类且标签相同」，逐条留痕
    记录 interleave_action / interleave_shift（相对 U 降序位后移几位）
```

- 主键 = 上位大类（8 类）；次级键 = 分类标签（国际动态取三类重大突发标签，其余取细标签）。`interleave_label_epsilon` 默认 1.0，设 0 即只看大类。
- **前窗强制**：前 `front_window` 条相邻同大类必须为 0，这是硬性验收项。
- front→tail 边界把 front 末条的大类与标签传进 tail 贪心，避免两段拼接处堆同类。
- 容量不足不造假：某大类条目远多于其他大类时，尾部无法完全避免同类相邻；逐条列「被迫连续」的位置、大类、标签与原因，不编造条目凑数。
- 开关：`interleave=false` 按纯 U 降序；`orchestrate=false` 按纯 `Final_adj` 降序。所用取值写进口径说明。
- 附录 14 对照表：展示序 / U 降序位 / 标题 / 上位大类 / 分类标签 / U / 打散动作 / 后移位数，并单列「被迫连续同类」清单；口径说明报告相邻同大类对数（前→后，前窗 / 全表分别）、相邻同标签对数、被迫连续处数。

### 4.13 主表去重与候选池分离

> 本节按定时任务 instruction 第六节同步。仲裁规则：instruction > 本 SKILL > 作业总表。

「处理后的数据」与「排名最靠前的10条」按事件主键去重，完全重复行必须为 0。「窗口内全部数据」是**筛选前的采集候选池**：只去采集层「标题 + 渠道 + URL 全同」的完全重复，不按事件主键去重、不做事件层或议题层合并、不施加贴近度筛选与三类强剔除；评级列（Final_adj / 等级 / 原始 Final / 分数序 / 事件主键）一律置「—」，展示序为采集序 1–N。

代表条的「来源」统一写 `渠道 · 渠道`，逐渠道列出；被合并的渠道记录一条不丢，全进附录 12b 逐条列事件主键、保留稿、被合并稿和来源。关系为：**窗口内全部数据（候选池）⊇ 主表 ⊇ 前 10**；候选池不截断、不删被筛掉或被合并的条目。

### 4.13.1 议题簇去重（同一议题的不同侧面）

事件层与议题层严格分离，两者不可混用：

| 层 | 判据 | 合并后 | 是否计入 `cross_score` |
|---|---|---|---|
| 事件层 `eid` | 同一件事的不同渠道稿，按共享数字锚点 / 事件词组 / 标题字面重合聚类 | 主表与前 10 各留 1 行，渠道明细进附录 12b；候选池不参与 | 是，独立信源数是可数序次信号 |
| 议题层 `sid` | 同一议题下不同侧面（如美伊冲突的袭击、使馆警报、油轮触雷、无人机打击） | 主表与前 10 每簇各留 1 条代表条，其余完整内容进附录 17；候选池不参与、各侧面全部保留 | **否**，不得把多家媒体虚增成同一事件的多渠道热度 |

议题词组表可配置，每组含 `name / subjects / actions`。判定条件：**主体词必须命中标题**（汇总稿与陈年稿件的摘要常夹带各种国名，允许摘要命中主体会把不相干稿件拉进簇），动作词可来自标题或摘要；至少命中 1 个主体词，且主体词与动作词合计命中 ≥ 2 个不同词，才归入该议题。

代表条优先取簇内基准分 `Final_adj` 最高者（该议题最突出的一条），其次按标题命中主体词数；不按摘要长度选——聚合稿往往摘要最长。展示序由编排层在去重后重新计算。代表条的「内容摘要」保持原文，不把被合并条的内容塞进该列。

`story_max_keep` 默认 1，可设为 2 以保留两条不同侧面；`story_dedup=false` 关闭整层。附录 17 逐条列议题名、代表条、被合并条标题与来源、摘要首段、命中主体与动作词组，完整内容不删除、不静默消失。

### 4.14 保护截断

用户指定「只保留 N 条」时，不能直接按 `Final_adj` 截前 N：展示分含同类递减，同一条新闻可能被压低 12–18 分，次要条目会挤掉原始分高但被递减压低的重要条目。

```
protected = 命中「重大伤亡 / 终局性新规 / 权威预警 / 重大司法终局」信息功能档位
            OR 原始 Final ≥ 70
选集 = Final_adj 前 N
       ∪ protected 中落在 N 外的条目
       ∪ 大类覆盖保底（某**未剔除**上位大类在选集中 0 条时，补其展示分最高的一条；
         准入层删除的大类跳过，不补回来）
若 |选集| > N → 剔除「非 protected 且 Final_adj 最低」的条目，直到恰好 N
最终仍按 Final_adj 单一降序呈现，不产生第二套位次
```

必须做反事实验证（把上限临时压到更小的数跑一遍）；被截断条目逐条留痕（全表展示序、展示分、原始 Final、是否 protected、大类、标题），不删除不改写；报告打散代价。

### 4.15 打分示例

用同一份清单的可数信号与信息功能档位演算，便于逐条复算。下表只给相对位次结论，具体 `V` / `Final` 按各批次实际 I/C 赋值与 `H` 通道状态重算。

| 条目 | 命中的最高信息功能档位 | 相对位次 | 说明 |
|---|---|---:|---|

## 5. 分类词表（仅作标签，不产生分组）

分类是两层：细标签用于检索、漏收校验与回测分层；上位大类只在同类边际递减中作为对称打散维度。两者都不产生任何章节、小节、版面分组、置顶、折叠或类目配额；细标签不进六维价值分，大类不进六维价值分、不改变等级。λ=0 时大类层完全不生效。

**8 个上位大类**：民生服务、财经市场、科技与产业、文娱与热榜、重要赛事、重大突发与司法、国际动态、社会治理与养老。

细标签须先归入大类，否则报错、不许留未映射项。细标签判定以**标题主体为准**（标题 ×3 + 摘要 ×1 加权），采集源显式大类优先；国际条目细标签强制走三类重大突发标签，细标签不能跨上位大类。典型约束：天气细标签不含泛词「预警」（否则「防空警报 / 安全预警」会把国际战事误标天气），赛事细标签不因摘要顺带提及「长沙马拉松」就误投。

## 6. 处理流程

1. 确定日期与采集窗口（默认 `(前一晚 20:00, 当晚 20:00]` 左开右闭）。
2. 按 8 个上位大类逐组采集，逐渠道申报触达状态；三条平台渠道走 `site:` 定向或外部注入。
3. 窗口过滤：超左界 / 超右界逐条写明时间证据；`pub` 缺失标「时点推定」。
4. 拼盘稿拆分优先：主体必留、裁罗列尾巴、拆出词条逐条回查独立原文；纯汇编母行剔母行。
5. 准入判定（大类级 → 大众贴近度 → 国际仅三类重大突发 → F1–F4），逐条留痕。
6. 同事件聚类与多渠道计数；主表与前 10 按事件去重，候选池不参与去重与合并，渠道记录进附录 12b；再按议题簇去重，同议题不同侧面进附录 17。
7. 七维打分 → 信息功能档位 → `Final` → 等级 → `gin`/`cap`/`Final_adj`。
8. 编排：编排分 U → 头部三席 → 同类上限与覆盖保底 → 相邻打散。
9. 指定条数时按保护截断，做反事实验证。
10. 摘要生成：取原文全文，>240 字才精简，分段换行 + 首行缩进。
11. 五工作表出表，写口径正文与附录 1–16。
12. 质检逐条打勾，交付。

## 7. 核实规范

- 每条成行数据必须有可点开的独立原文 URL；金额、百分比、比分、人数、日期能在来源索引找到出处，未核实数字不作结论。
- 查不到原文的条目只留标题，无脑补内容；三态核实与封顶生效。
- 标题—正文五项（主体、时间、地点、结果、影响）一致性检查。
- 一家之言标注主体（「律师指出」「专家建议」「警方提示」），不写成既定结论。
- 多来源口径冲突并列标注、不私自择一；赛事比分 / 行情注明快照时点。
- 健康、法律、金融类结论有具名机构或专家支撑。
- 补实摘要不改 `I/C/V/Final` 基准。

## 8. 摘要撰写规范

12 列里唯一需要生成的展示字段是「内容摘要」。

| 规则 | 做法 |
|---|---|
| **底稿** | 取原文摘要全文，保留事实骨架、句式与数字 |
| **精简** | 仅当 >240 字时精简：按**整句 / 整分句累加**选取（含数字、含结论词、首句优先），累加到不超过 240 字；**绝不 `[:max_len]` 切句**，宁可略超长也不留半截。删冗长枚举、次要背景与重复，数字一个不改 |
| **占位句** | 全部删除。代码、LLM 提示词、产出单元格三处都不得出现「详情以原文为准」或等价推卸语；附录 5b「占位句残留」必须为 **0** |
| **分段** | 2–3 个自然段，段间 LF（恰好 1–2 个换行符），每段首行缩进 `　　`（U+3000 × 2），无 CRLF |
| **单句** | 就是单段，不硬造第二段；短句自动合并避免碎段 |
| **原文缺失 / 过短** | 用标题补成完整陈述（直接成段、不加「据标题概述」前缀、不编造数字与细节）；`abstract_source` 标「标题补全（原文摘要缺失 / 过短）」并逐条留痕，读者可从「来源」列点开原文 |
| **收束检查** | 末段无句末标点且不完整时，用标题补一个完整陈述段 |
| **热榜词条** | 必须讲清大概：谁 / 何时 / 何地 / 数字 / 发生了什么 / 可行动项；只有话题名 + 热度、查不到事件正文的词条按独立原文准入剔除 |
| **同事件** | 多渠道复用同一摘要 |

- 标题负责识别，摘要负责「读完不用再点开原文」。
- 数字必须带单位与时间；不用「大幅」「显著」「多数」等无锚点形容词。
- 相邻条目避免句式重复；不写「根据搜索结果」「按内部规则」等过程性表述。
- 未配 LLM 时是抽取式近似，不会凭空扩写；配 LLM 后可基于标题生成更完整概述，但提示词仍须禁止编造数字、禁止占位句、禁止截断句子。
- 附录 5 摘要长度对照（数字未改写）与附录 5b 摘要来源留痕为交付必备。

**固定结构（每条 80–250 字）**：一句话定性 + 关键事实（谁 / 何时 / 何地 / 数字 / 发生了什么）+ 背景或成因 + 对读者的影响与可行动项 + 必要的口径限定或风险提示。元信息行另列 `〔清单 #N〕`、分类、大类、`Final_adj`、`Final`、`gin`/`cap`、`H`、`V`、信号构成、核实来源。

## 9. 合并 / 拆分 / 剔除

- **合并**（保留全部编号）：同一事件不同阶段、同一人物多个热搜、同一主题多条简讯、清单条目 + 联网补齐的同窗口内容。
- **拆分**：一个条目塞了多个独立事实且各自够 A 级以上 → 拆成主条 + 背景条，未核实部分单独标注。
- **剔除但在附录留痕**：观察池 / 未核实条目、被条数上限截断的条目，写清「剔了什么、为什么、分数是多少」，不悄悄丢弃。不因分类剔除、不因分类后置。用户改口径（如「不设限」「赛事也要」）时只需重跑第 5、8、9 步，不必重新联网核实。

### 11.1 发布时间字段契约

> 以下 11.1 为**仓库侧采集链路**的字段细则，供需要接入 `latest.json` 时参考；定时任务与会话内补跑批次不产出该文件，逐条时间依据单列留在口径表与「候选池边界留痕」，不编为第 18 号附录。

`latest.json` 的每条 `items[]` 与 Excel 附录 18 须逐条给出四个时间字段：

| 字段 | 契约 |
|---|---|
| `发布时间` | 采集源 `pubDate`、搜索 API `date` 字段、正文标准新闻时间戳或外部注入 `pub`；取不到写字面值「未取得」 |
| `时间依据` | 上述取值来源；未取得时写明「近一天收录，不等于发布于当日」 |
| `时效标记` | 窗口内实证 / 正文日期推定 / 近一天推定 / 当日速览推定 / 往期日期线索·需核对，五者之一 |
| `日期线索` | 标题与摘要里出现的月日串，只留痕 |

搜索 API 的 `tbs=qdr:d`（Serper）与 `days=1`（Tavily）保证的是「近一天被搜索引擎收录」，不是「发布于当日」。周报、月度盘点、往期复盘稿、公司档案页可能在近一天被重新抓取，不得据此写成当日发布。

相对时间串（如 `16 hours ago`）是抓取时刻倒推，只登记进「时间依据」的说明，不换算成 ISO 时间写进「发布时间」。标题或摘要里的月日可能是事件日期、周报覆盖区间或往期复盘，只写进「日期线索」，不据此剔除条目、不据此反推发布时间。

当日速览推定只用于本身无逐条 `pubDate` 的聚合快讯流与社交平台当日热榜词条。搜索 API 的每条结果一律按「近一天检索」标注。

口径正文须包含：检索截止时间、采集窗口与零缺口规则、时间证据分布、发布时间字段契约、渠道触达率、贴近度档位与大众贴近度判定、三类强剔除逐类计数与正面清单命中数、国际动态仅重大突发声明、编排层与头部三席开关取值、H 通道状态、时点推定的 T 处理、`gin` 计数口径、摘要规范、等级按原始 Final 声明、前 10 覆盖大类数、相邻同大类对数、多渠道事件数与加分条数、国际资讯保留 / 剔除 / 重要条数与三类逐类计数、议题簇合并条数与簇数、结构校验结果。三类重大突发若某类 0 条须写明是采集缺口；按大众贴近度口径剔除导致的 0 条须写明「按大众贴近度口径剔除，非采集缺口」；零国际条目须声明非规则清空。

## 13. 常见坑与实战处理

| 坑 | 表现 | 处理 |
|---|---|---|
| 跨平台数值相加 | 微博热度值 + 抖音播放 + 百度指数求总 | 各平台先转百分位，跨平台只加百分位 |
| NULL 补零 | 「没抓到数据」当成「热度为 0」 | 走六维条件式（分母 0.82） |
| 二次归一化 | 发现最高才 85.5 就整体拉到 100 | 禁止，破坏回测可比性 |
| 把类别占比当阅读量 | 用「垂直 38%」证明科技比民生更热 | 那是榜单词条数量占比，不是阅读 / 讨论总量 |
| 把热榜当事前预测或信源 | 用热搜词替代原文 | 热榜是事后聚合，须回查独立原文 |
| 爆款解读升格为事实 | 政策短视频当成政策原文 | 原文仍是核验入口 |
| 情绪 / 名人抬重要性 | 明星争议因讨论高就进 A 级 | 只进 `M`（≤5），不进 `I`/`C`；无新事实扣 −4 |
| 榜单词强行补摘要 | 只给话题名 + 热度值 | 按独立原文准入剔除；查得到正文才成行 |
| 拼盘稿一刀切 | 把「资讯早餐」整条删掉，主体事件和同榜词条一起消失 | 拆分优先：主体必留、词条拆出成行 |
| 字段内换行被按行切 | 自己 `file.split('\n')` 把一条新闻拆成三行 | CSV / JSON 的字段内换行是安全的，用标准 reader；或按 `\n` 切段再 trim |
| 把缩进当数据 | 全角空格参与语义判断 | 缩进是纯视觉字符，解析前 trim |
| 同事件标题不同就各留一行 | 多渠道转载稿重复成行 | 按共享数字锚点 / 事件词组聚类，主表与前 10 统一去重，候选池不去重 |
| 同一冲突的不同侧面各占一行 | 读者看到四条都在讲美伊冲突 | 按议题簇收敛，每簇留代表条，其余进附录 17 |
| 汇总稿摘要里夹带国名就被并进议题 | 陈年稿件抢当代表条 | 主体词只认标题，动作词可看摘要；代表条按标题贴题度选 |
| 数字锚点误聚 | 「11月16日」把泰国火灾和央行逆回购聚成一件事 | 数字须带单位或小数 + 标题共享中文实词 |
| 叙述性尾巴被切成假词条 | 「援引报道称…维持在96美元下方」拆出三行 | 叙述碎片不拆，它只是主体事件的补充数据 |
| 境外条目投进国内大类 | 日本地震归「民生服务」第 1 | 境外主体信号前置，优先归国际动态 |
| 泛词「预警」误标 | 「防空警报 / 安全预警」把国际战事标成天气 | 天气细标签用词组，不用裸词 |
| 标题里的数字没核实 | 标题写「单月贸易顺差超 1335 亿美元」 | 正文只写已核实数据，该数字单独注明「本次未核实，不作结论」 |
| 两个口径打架 | 事故「约 50 人住院」vs「40 余人受伤」 | 并列写出 +「口径不一，以官方为准」，不删任一条 |
| 入口页当新闻 | 清单前几条是部委官网首页 | 字段不合格 → 未核实 → 观察池 |
| 为达标手工挪位次 | 想让某类进前 10 就调分数 | 编排层只改展示序；不足时如实写明代价 |
| 覆盖统计漏算头部 | 前 10 覆盖大类数虚低、换入条目被挤出 | 覆盖统计含头部三席，`front_cap` 扣减占席 |

## 15. 边界声明

- **`Final` 是合成判断分，不是实测值**；`H` 是传播足迹代理变量，不是真实浏览量 / 讨论量；`W_H = 0.262` 是审慎先验而非因果估计。三者须在交付物开头写明。
- **无平台后台数据时 H 通道关闭**，`P`/`H` 置 NULL、`Final = V/82.32×100`，清单按编辑价值判断排序。此时娱乐、赛事系统性偏低是数据缺口而非重要性判断，不得把 `H` 称为「实测热度」，也不得用可数信号构造虚假 `H`。
- **多渠道重复度是独立信源计数**，不进 H / V / Final，只进编排分 U；若真实批次全部单源，该项自动不生效，如实写 0、不编造。
- **分类只作标签与对称打散维度**，不进六维价值分、不改变等级、不产生分组、不做类目配额。`cap` 由信息功能档位触发，与类目无关。
- **编排层、头部三席、相邻打散、覆盖保底只改展示序**：`Final` / `Final_adj` / 等级 / `gin` / `cap` / `V` / `I` / `C` 数值一律不改，原始分数序完整保留、可逐条复算。`orchestrate=false` 回到纯 `Final_adj` 降序；`head_window=0` 关闭头部独立判定；`interleave=false` 关闭相邻打散。展示序与 `Final_adj` 严格降序不一致是编排口径的代价，须如实标注。
- **准入层只决定收不收**，不进评分、不改等级、不移位次；被剔条目逐条留痕、不删不改。大众贴近度准入默认关闭，须用户显式下达才启用。
- **渠道触达如实申报**：无公开接口、无 key、被出口策略拦截时写「未触达」及原因，不得推断成「原文无配图」或「该平台无内容」，也不得编造条目凑数。窗口外条目逐条写明时间证据，不回溯补采、不推测补写。
- **发布时点**：只有日期或时段词的标「时点推定」，不补造具体时刻；`pub` 缺失取批内已知时刻年龄中位数。
- **摘要不编造**：原文缺失 / 过短时用标题补成完整陈述，不凭空扩写细节；未配 LLM 时是抽取式近似，口径表须标注。
- **不构成投资、医疗、法律或出行决策建议**。
